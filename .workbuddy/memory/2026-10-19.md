# 2026-10-19

## 定时同步「静默失败」排查与加固

**现象**：连续 4 天（10-16 ~ 10-19）08:30 定时同步失败，看板整天是 0 条空数据；08:55 手动同步必成功（741 只）。

**根因链**：
1. `get_qdii_universe()` 第 1 页拿到 HTTP 200 但非预期响应（推测为 null / 风控 HTML / BOM）→ `json.loads` 后 `.get("Datas")` 抛错 → except 打「第 1 页解析失败」→ break，全集变 0。
2. 单页失败即整轮放弃，**没有整体重试**。
3. main 不管数据好坏照写 `quota_data.json` / Excel / 静态 HTML，**0 条覆盖掉昨天的好数据**。
4. 退出码仍是 0 → scheduler 看到 `updated_at` 是今天 → 判定「今日已同步」，不再重试。

机器 09/06 起未重启，排除开机网络未就绪；差异只在 08:30 这个时间窗口（天天基金早间数据更新/缓存刷新期接口不稳定）。

**已实施修复**：
- `sync_data.py`：新增 `parse_json()`（剥 BOM、区分空响应/非 JSON/非对象）；`_rank_page` 单页重试 2 次；`get_qdii_universe()` 整体重试 3 轮（退避 20s/40s）+ 兜底复用上次 `_universe.json`（source=fallback）；异常响应落盘 `_bad_response.log`。
- `sync_data.py` main：**健康校验**——条数 < `QDII_MIN_ROWS`(500) 或 < 上次 80% 时放弃写入并 `sys.exit(3)`；全集为空 `sys.exit(2)`。
- `app.py`：rc != 0 或条数不足判失败；当天自动重试最多 3 次、间隔 20 分钟（`QDII_RETRY_MAX` / `QDII_RETRY_GAP`）；`attempted_date` 防止 30s 循环狂重试；`/api/meta` 增 `next_retry`、`retry_count`。
- 验证：`QDII_MIN_ROWS=99999` 演练 → rc=3、数据未覆盖、自动排定重试；真实同步 741 条 rc=0。服务已重启加载新逻辑。

**遗留建议**：若明早仍失败，可把定时时间从 08:30 推到 09:10（改 `start_server.bat` 加 `set QDII_SYNC_HOUR=9` / `set QDII_SYNC_MINUTE=10`）；失败响应样本次日看 `_bad_response.log` 即可确认是 null 还是 HTML 风控页。
